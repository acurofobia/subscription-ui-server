# Сервер данных подписки · версия 1

Контракт UI версии 1 для единого сервера VPN-конфигурации и интерфейса.

## Назначение

Отдельный сервер выдаёт приложению содержимое готовых интерфейсных блоков
из редактируемого UTF-8 JSON-файла. Названия блоков и элементов обезличены:
`block01`, `button01`, `option01`, `page01`. Назначение определяется текстом,
типом компонента и действием. У сервера нет зарезервированных бизнес-полей.

Сервер выдаёт VPN-подписку, VPN-конфигурацию и данные интерфейса с одного порта.
Android- и iOS-клиенты получают адрес UI и токен из единой подписки. Платежи и база
пользователей находятся вне этого сервера.
Одна инстанция выдаёт один документ; персонализации по пользователям нет.
Необязательные решения доступа TURN задаются отдельно для каждого HWID в JSON.

## Архитектура и запуск

- Python 3.11+, только стандартная библиотека; установка пакетов не требуется.
- `server.py` — CLI и HTTP-сервер; `validation.py` — чтение и проверка UI;
  `provisioning.py` — VPN-конфигурация и адаптер локального Xray JSON.
  `device_access.py` — файловые решения протокола `device-access-v1`.
- Настройки в `.env` рядом с `server.py`; defaults: `127.0.0.1:8082`.
- Аргументы: `--env`, `--host`, `--port`, `--data`, `--check`.
- `--check` проверяет токен, UI, включённый VPN-конфиг и правила доступа без открытия порта.
- Пути в `.env` относительно самого `.env`; `--data` относительно текущего
  каталога. UI по умолчанию — `data/subscription.json` рядом с `.env`.
- В репозитории поставляется `data/subscription.example.json`: перед запуском
  скопируйте его в рабочий `data/subscription.json`, исключённый из Git.
- При старте сервер проверяет UI. Ошибка файла или параметров завершает запуск.
  VPN-конфиг проверяется при его запросе и при `--check`.
- Каждый запрос данных заново читает и проверяет файл: изменения работают
  без перезапуска. Рекомендуется сохранять редактором через атомарную замену.
- Файл ограничен 1 MiB. Проверка выполняется и при запуске, и при запросах.

## HTTP API

| Метод и путь | Ответ |
|---|---|
| `GET /subscription/<token>` | 200: `sing_box_url`, `vk_turn_link`, `ui_url`, `ui_token` |
| `GET /subscription/<token>/config` | 200: VPN JSON-объект, максимум 8 MiB; 404, если выключен |
| `GET /v1/subscription` | 200: проверенный UI-документ целиком |
| `GET /subscription/<token>/app/v1/ui` | Тот же UI-документ; нативный Bearer |
| `GET /subscription/<token>/app/v1/config` | Нативный конфиг; Bearer и согласование capability |
| `HEAD /v1/subscription` | Те же код и заголовки, без тела |
| `GET /health` | 200: `{"status":"ok"}` — процесс доступен; файл не проверяется |
| `HEAD /health` | Те же заголовки без тела |
| Остальные пути | 404: `{"error":"not_found"}` |
| Иные методы | 405: `{"error":"method_not_allowed"}`, `Allow: GET, HEAD` |

Query-параметры не влияют на ответ. Файлы проекта не раздаются, включая JSON,
спецификацию и любые пути с `..`. Отдельного метода записи данных нет.

Общие заголовки: `Content-Type: application/json; charset=utf-8`, корректный
`Content-Length`, `Cache-Control: no-store`, `X-Content-Type-Options: nosniff`.
JSON выдаётся с Unicode без ASCII-экранирования; NaN и Infinity запрещены.

Если после запуска файл исчез, испорчен или не соответствует контракту,
endpoint данных возвращает 503 `{"error":"subscription_unavailable"}`.
После исправления следующий запрос снова работает. Сервер не подменяет ошибку
устаревшими данными; последние успешные данные должно сохранять приложение.
HTTP-ошибки не раскрывают пути, значения файла, токен или traceback.

## Доступ

В `.env` обязателен `SUBSCRIPTION_TOKEN`: 16–256 символов `[A-Za-z0-9_-]`.
Единая подписка и исходный VPN endpoint проверяют этот токен в пути.
UI требует ровно один заголовок `Authorization: Bearer <token>`; query-токены
не принимаются. Исходный UI использует токен подписки. Нативные endpoint
принимают `ui_token` из дескриптора, при настроенном секрете — HMAC-токен.
Неверный токен в пути даёт 404, неверный UI Bearer — 401 с `WWW-Authenticate: Bearer`.
Сравнения выполняются за постоянное время. `/health` открыт и не читает файлы.
Токен, пути и данные перечитываются на каждом запросе. Менять `HOST`/`PORT` нужно
с перезапуском; менять токен — с заменой ссылки в приложении.

Ссылки формируются из `PUBLIC_BASE_URL`, если задан, иначе из проверенного
`Host`; неверный Host даёт 400. Access log отключён. Для публичного развёртывания нужен HTTPS
reverse proxy; сам сервер TLS не реализует. HTTP в домашней сети передаёт
токен и VPN-параметры без шифрования. Сетевой таймаут чтения — 10 секунд.

## Формат документа

Корень содержит ровно `schemaVersion`, `blocks`, `pages`.
`schemaVersion` — целое число 1, не boolean. `blocks` и `pages` — массивы.
Неизвестные поля и типы отвергаются: расширение контракта требует новой версии.
Порядок элементов в массивах сохраняется. Сервер не добавляет собственные поля.
Оба UI-маршрута возвращают документ без подстановок и вычислений. Содержимое
блоков и их состояния не зависят от VPN-конфигурации или возможностей клиента.
Любые тексты, отформатированные числа, ссылки и пояснения задаются в JSON.
Для `block01`–`block06` сервер проверяет типы, закреплённые текущим клиентом:
`card`, `valueRow`, `actionSheet`, `selectionList`, `menu`, `progress` соответственно.
Это технические слоты, которые не задают значения оплаты или баланса.

Все `id` уникальны во всём документе, регистрозависимы, соответствуют
`[A-Za-z][A-Za-z0-9_-]{0,63}` и не зависят от отображаемого текста.
`targetId` и `detailsPageId` — ссылки, поэтому не объявляют новые идентификаторы.

Общие поля блоков: обязательные `id`, `type`; необязательные `visible`
(boolean, по умолчанию true), `title`, `subtitle`, `text`. `visible` означает,
что компонент разрешено показывать, а не что модальное окно уже открыто.
Размещение блоков по экранам закрепляется в приложении по ID.

Строки заголовков и подписей: 1–4096 символов. `text` может быть пустым,
до 4096 символов. `pages[].text` — до 32768 символов, обычный текст без HTML.

### Типы блоков

| `type` | Дополнительные обязательные поля | Другие допустимые поля |
|---|---|---|
| `card` | `title`, `buttons` | Общие поля |
| `valueRow` | `title`, `buttons` | Общие поля |
| `actionSheet` | `title`, `buttons` | Общие поля |
| `selectionList` | `items` | Общие поля |
| `menu` | `items` | Общие поля |
| `progress` | `value`, `maximum`, `unit` | Общие поля, `period`, `resetAt` |

`buttons` — массив, может быть пустым. Кнопка содержит обязательные `id`,
`title`, `action`, необязательный `visible`.

Пункт `menu.items` имеет тот же формат, что кнопка.

Пункт `selectionList.items` содержит обязательные `id`, `title`, `text`,
`state`, `buttons`; необязательные `visible`, `stateText`, `detailsPageId`.
`state`: `available`, `restricted`, `unavailable`.
`stateText`: непустая строка или null; `detailsPageId`: ID страницы или null.
Ограниченный/недоступный пункт нельзя выбрать. Текущий выбор хранит приложение.
Для restricted приложение показывает состояние и кнопки вместо «Подробнее».

`progress.value` и `maximum` — целые числа от 0 до 9007199254740991;
`maximum` больше нуля, `value` не больше `maximum`. `unit`: `bytes`, `count`,
`percent`. Необязательный `period`: `day`, `week`, `month`, `total`.
`resetAt`, если есть: ISO 8601 datetime с часовым поясом либо null.
Приложение форматирует числа и строит индикатор; сервер не считает трафик.

### Действия

| `action.type` | Единственное дополнительное поле | Значение |
|---|---|---|
| `openExternalUrl` | `url` | Абсолютная HTTPS-ссылка, максимум 2048 символов |
| `openScreen` | `targetId` | ID встроенного экрана |
| `openBlock` | `targetId` | ID существующего блока `actionSheet` |

HTTPS-ссылка требует hostname, запрещает userinfo, пробелы, управляющие символы,
обратный слеш и некорректный порт. Telegram открывается через `https://t.me/...`.
Сервер ссылки не запрашивает и их доступность не проверяет.

`openScreen` ссылается на экран приложения, которого нет в `blocks`.
На стороне приложения `screen01` — форма изменения ссылки подписки.
Неизвестный приложению экран не должен запускать произвольное действие.

`pages` — массив объектов с обязательными `id`, `title`, `text`.
Ненулевой `detailsPageId` должен ссылаться на существующую страницу.

### Пример привязки в приложении

| ID | Предполагаемая привязка первого клиента |
|---|---|
| `block01` | Общая карточка на главном экране и в профиле |
| `block02` | Строка с крупным значением и кнопкой |
| `block03` | Модальное окно выбора внешней ссылки |
| `block04` | Список вариантов подключения |
| `block05` | Дополнительные пункты профиля |
| `block06` | Индикатор числового значения |
| `option01` / `option02` / `option03` | Варианты подключения клиента |

Это документация клиентских привязок; названия и значения задаются в JSON.
Подробные ограничения отображения текущего клиента перечислены в README.
Сервер не назначает технический режим по тексту и не выполняет действия.
Локальные «Обновить», «Отмена», логи, настройки, VPN-статус и время обновления
не передаются. Начальный экран клиента показывает форму единой ссылки без встроенных внешних ссылок.

## Приёмка

Весь набор тестов запускается `python3 -m unittest discover -s tests -v`.
Проверяются документ-пример, ошибки структуры и ссылок, ограничения чисел,
строк и URL, повторяющиеся JSON-ключи и идентификаторы, реальный HTTP,
перечитывание и восстановление файла, авторизация, недоступность файлов,
HEAD/405, одинаковые заголовки ошибок и отсутствие утечки данных.
README содержит точные команды запуска, проверки и обращения к API.

## Интеграция клиента

Android-клиент `Vipin` и iOS-клиент `VKTurnPrototype` получают `/subscription/<token>`, затем VPN-конфиг
по `sing_box_url` (если включён) и UI по `ui_url` с Bearer `ui_token`.
Обе ссылки должны использовать тот же origin, что исходная ссылка клиента.
Для обычного HTTP по LAN применяется исходный формат; по HTTPS или loopback
HTTP доступен нативный `vipin-v1`. Согласование формата и HMAC описаны в README.
Android release требует HTTPS; loopback/LAN HTTP доступны только debug APK,
а нативные решения устройств — только по HTTPS или loopback HTTP.
`UI_DOCUMENT_PATH` задаёт локальный UI JSON, `SING_BOX_CONFIG_PATH` — VPN JSON,
`VK_TURN_LINK` — необязательную ссылку VK TURN. Пустые транспортные настройки
дают `null` в соответствующих полях и не мешают выдаче UI.

JSON UI версии 1 не изменился. Приложение проверяет и сохраняет весь комплект
атомарно; ошибка обновления сохраняет прежний кэш и не перезапускает VPN.

При настроенном `DEVICE_ACCESS_PATH` дескриптор требует нативный
`device-access-v1` и один `x-hwid` формата `[A-Za-z0-9=-]{10,64}`.
Политика — JSON с точными полями `schemaVersion: 1`, `default: {state, revision}`,
`devices: {hwid: {state, revision}}`; неизвестные поля запрещены.
Решение устройства заменяет default. Состояния: `allowed`, `not_allowed`,
`device_revoked`, `device_limit_reached`. Ревизия — целое 0…9223372036854775807.
Ответ содержит `device_access: {schemaVersion: 1, hwid, state, revision}`;
при запрете TURN-ссылка равна null, VLESS/UI остаются независимыми.
Android сохраняет запрет до полного нового комплекта с `allowed` более высокой
ревизии. Ревизии задаёт оператор; лимиты и регистрацию сервер не рассчитывает.
Файл проверяется при старте, `--check` и каждом запросе дескриптора; максимум 1 MiB.
Ошибки: 400 — HWID, 406 — отсутствие нативной capability, 503 — файл правил.
`Vary` нативных ответов включает `x-hwid`. Без политики формат дескриптора прежний.
